# ترقية Smart Device Identity v2

هذه الترقية تطور النظام الحالي دون Passkey أو بريد إلكتروني، مع الحفاظ على أن المفتاح العشوائي للمتصفح والـCookie الموقعة هما أقوى دليل للهوية.

## ماذا يحدث عند تسجيل الدخول؟

1. **تطابق مؤكد:** نفس مفتاح المتصفح + نفس الـCookie الموقعة → استعادة الكنية مباشرة.
2. **تطابق ذكي قوي:** إذا فُقد المفتاح، يقارن السيرفر مجموعات مستقرة من الإشارات المشفرة فقط، ويستعيد الكنية تلقائيًا عندما تكون النتيجة مرتفعة وغير متقاربة مع مستخدم آخر.
3. **تأكيد المستخدم:** إذا كانت النتيجة جيدة ولكن غير كافية للدخول التلقائي، تظهر حتى 3 كنيات مرتبة حسب درجة التوافق. الاختيار لا يرسل `user_id` مباشرة؛ بل يستخدم تذكرة موقعة لمدة 5 دقائق، ثم يعيد السيرفر الحساب والتحقق قبل ربط الكنية.
4. **جهاز جديد:** إذا لم توجد نتيجة آمنة، يختار المستخدم كنية جديدة. لا يتم التخمين القسري.

## قواعد الأمان المهمة

- الدخول التلقائي يبدأ من **94% توافق** مع فرق لا يقل عن 12 نقطة عن أقرب مستخدم آخر.
- يجب توفر 3 مجموعات قوية على الأقل، مع عدم وجود أكثر من تعارض ثابت واحد.
- سجل واحد يمكن أن يسمح بالدخول التلقائي فقط إذا تكرر بنجاح 3 مرات على الأقل، وكانت النتيجة 97% أو أكثر مع 4 مجموعات قوية وبدون تعارضات.
- الاختيار اليدوي من المقترحات يحتاج 78% على الأقل، ومجموعتين قويتين، ثم يعيد السيرفر التحقق.
- عنوان IP والبطارية والشبكة إشارات ضعيفة ولا يمكنها اختيار كنية بمفردها.
- كل القيم المخزنة في أعمدة المطابقة الجديدة هي HMAC hashes؛ لا يتم تخزين Serial Number أو MAC Address أو بصمة خام.

## طريقة التركيب

1. خذ نسخة احتياطية من مجلد المشروع الحالي.
2. انسخ محتويات ملف الترقية فوق مجلد المشروع الحالي، واختر **Replace files in destination**.
3. داخل CMD في مجلد المشروع نفذ:

```cmd
git status
git add .
git commit -m "Upgrade smart device identity v2"
git push origin main
```

4. انتظر حتى يصبح Deployment في Cloudflare ناجحًا.
5. افتح Supabase → SQL Editor، وشغّل مرة واحدة فقط:

```text
SUPABASE_SMART_DEVICE_IDENTITY_V2.sql
```

الملف آمن لإعادة التشغيل، ولا يحذف المستخدمين أو الكنيات أو الرسائل.

## اختبار سريع بعد النشر

- نفس المتصفح مع نفس المفتاح: يجب أن يستعيد الكنية مباشرة.
- Private أو بعد حذف التخزين: إن كانت المطابقة مؤكدة جدًا قد يدخل تلقائيًا، وإلا تظهر أفضل 3 كنيات.
- جهاز مختلف أو نتائج متقاربة: لا يجب أن يدخل تلقائيًا.
- زر **ولا واحدة منهم** يفتح تسجيل جهاز وكنية جديدة بدل ربط كنية خطأ.

## مفتاح إيقاف طوارئ اختياري

يمكن إضافة متغير بيئة في Cloudflare باسم:

```text
SMART_IDENTITY_MODE
```

القيم:

- `smart` — الوضع الافتراضي: دخول تلقائي آمن + اقتراحات.
- `suggestions` — يمنع الدخول الذكي التلقائي ويعرض الاقتراحات فقط.
- `exact` — يستخدم المفتاح الدقيق والـCookie فقط، ويوقف كل المطابقة التقريبية.

بعد تغيير المتغير اعمل Deployment جديد.

## الرجوع للخلف

لإلغاء كود الترقية، استخدم `git revert` للـCommit الخاص بها. ولإزالة أعمدة SQL الجديدة اختياريًا شغّل:

```text
SUPABASE_SMART_DEVICE_IDENTITY_V2_ROLLBACK.sql
```

لا تستخدم `git push --force`.

## ملاحظة واقعية

هذا أقوى نظام ممكن داخل موقع ويب دون Passkey أو وسيلة تحقق خاصة بالمستخدم، لكنه ليس بصمة هاردوير مضمونة 100%. لذلك صُمم ليفضل طلب التأكيد على أن يعطي كنية شخص لمستخدم آخر.
