# ترقية الهوية الذكية النهائية — SR Tool

هذه الترقية تُركَّب فوق النسخة الحالية التي تحتوي على Trusted Device Identity وإصلاح تعارض Cookie/Browser Key.

## ما الذي تغيّر؟

1. **المفتاح الموثوق أولًا**
   - نفس مفتاح المتصفح + Cookie الموقعة = استعادة مباشرة لنفس `user_id` والكنية.

2. **مطابقة ذكية متعددة الإشارات عند فقد المفتاح**
   - تقارن مجموعات مستقلة: العتاد الظاهر للمتصفح، الرسم WebGL/Canvas، نظام التشغيل، عائلة المتصفح، اللغة والمنطقة الزمنية، وإشارات مساعدة منخفضة الوزن.
   - لا يعتمد القرار على IP وحده أو البطارية أو سرعة الشبكة.
   - يجمع آخر الملاحظات التاريخية لكل مستخدم بدل الاعتماد على لقطة واحدة.

3. **قرار تلقائي محافظ**
   - الاستعادة التلقائية تتطلب درجة مرتفعة جدًا، أدلة كافية، عدة مجموعات قوية، عدم وجود تعارض ثابت، وفارق واضح عن أقرب مستخدم آخر.

4. **اختيار آمن عند عدم اليقين**
   - بعد صحة Username/Password فقط، تظهر بحد أقصى 3 كنيات محتملة إذا كانت كل واحدة اجتازت الحد الأدنى الآمن.
   - الواجهة لا ترسل `user_id` مباشرة؛ ترسل Choice ID عشوائيًا داخل Ticket موقعة مدتها 5 دقائق ومربوطة بنفس بصمة النافذة.
   - السيرفر يعيد حساب التطابق مرة ثانية قبل قبول اختيار المستخدم.
   - يمكن اختيار «ولا واحدة منهم» وتسجيل جهاز جديد.

5. **تعلم تلقائي**
   - بعد دخول صحيح، تُحفظ الملاحظة الجديدة لنفس المستخدم، فتتحسن فرص الاستعادة في الجلسات التالية من غير تواصل مع المستخدم.

## الملفات التي يجب نسخها

انسخ محتويات ملف الـPatch فوق مجلد المشروع الحالي، واختر Replace عند ظهور ملفات متكررة.

## أوامر الرفع

```cmd
git status
git add .
git commit -m "Final smart identity recovery upgrade"
git push origin main
```

انتظر نجاح Cloudflare Deployment.

## خطوة Supabase

بعد نجاح النشر، افتح Supabase > SQL Editor وشغّل مرة واحدة:

```text
SUPABASE_SMART_DEVICE_IDENTITY_V2.sql
```

الملف آمن لإعادة التشغيل، ولا يحذف مستخدمين أو رسائل أو كنيات. يضيف أعمدة Hash وفهارس فقط إلى `support_user_devices`.

## اختبار القبول

1. نفس المتصفح العادي: يجب أن يدخل تلقائيًا بالمفتاح الموثوق.
2. نافذة Private جديدة أو بعد فقد تخزين المتصفح:
   - إذا كان التطابق شديد القوة: دخول تلقائي.
   - إذا كان قويًا لكن غير حاسم: تظهر أقرب الكنيات للاختيار.
   - إذا كانت الأدلة ضعيفة أو متعارضة: لا يتم تخمين كنية، ويُطلب تسجيل كنية جديدة.
3. عند ظهور اختيارات متقاربة، لا يجب اختيار أي كنية تلقائيًا.

## ملاحظة أمان مهمة

هذه أقوى هوية صامتة عملية داخل متصفح من غير Passkey أو بريد أو رقم خاص بالمستخدم، لكنها ليست Serial Number للهاردوير ولا يمكن ضمانها 100% بعد حذف كل بيانات المتصفح. لذلك الترقية تتعمد رفض التخمين عند الشك بدل إعطاء كنية شخص لمستخدم آخر.

## الرجوع عن أعمدة قاعدة البيانات

عند الحاجة فقط، يوجد:

```text
SUPABASE_SMART_DEVICE_IDENTITY_V2_ROLLBACK.sql
```

لا تشغله في الاستخدام الطبيعي.
